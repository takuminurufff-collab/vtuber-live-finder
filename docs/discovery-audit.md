# うぶごえライブ：網羅性・無料運用の調査メモ

## 調査時点の事実
- 収集対象はコード上では日本の「個人勢VTuber」。事務所所属と思われるチャンネルを除外している。
- 発見経路は4タグの動画検索、毎回1組のライブ検索、既存チャンネルからのリンク・@ハンドル・おすすめチャンネル欄。
- タグ検索の未処理期間が3日を超えると、古い期間を切り捨てる (`SWEEP_MAX_LAG`)。検索の結果数が多い場合も、細分化の下限とページ上限があるため取りこぼしうる。
- 新規チャンネルで登録者数が非公開の場合、現在は採用せず「拒否済み」に入る。
- `looks_vtuber` は特定キーワードを含むかで判定。活動実態の見落としと誤判定が起こりうる。
- `is_corporate` は説明欄の文字列から判定。事務所所属の判定を保証しない。
- ライブ中の同接はすでに `live.viewers` に格納している。現在のWeb画面には同接の上限検索を追加する開発ブランチがある。
- 公開サイトはGitHub Pagesであり、メインブランチに変更を反映するまでは公開サイトを変更しない。

## 改善方針（未実装）
1. **対象定義**：個人勢のみの前提を廃止し、日本のVTuber（企業勢含む）を候補として保存する。分類は `indie/corporate/unknown` の属性とし、誤判定で削除しない。
2. **発見と判定の分離**：候補チャンネルと確定チャンネルを別状態で保持し、登録者非公開や説明不足を「VTuberではない」と即断しない。
3. **収集経路を追加**：既存経路に加え、非タグ検索クエリの巡回、協力者からのチャンネル登録、対象サイトから利用許諾を得たディレクトリの突合を検討する。
4. **漏れ率の測定**：外部の独立した参照集合を作り、「参照集合で発見済み/未発見」の割合と個別チャンネルIDを記録する。全数保証とは区別する。
5. **検索の進捗管理**：タグ・クエリごとの最終成功日時、取りこぼしを示すオーバーフロー、取り直しキュー、失敗回数を保存。3日超過の切り捨てを黙って行わない。
6. **コスト制約**：YouTube Data APIの無料日次クォータとGitHub Actions無料枠を監視。外部有料APIや課金設定は導入しない。
7. **ライブ鮮度**：同接0と不明を分け、ライブ最終確認時刻を保存する。公開Webで「リアルタイム」と言い切らず、更新間隔を明示する。
8. **動画本数の妥当性**：プレイリストの件数とYouTube UIをサンプル突合してShorts・通常動画・ライブアーカイブの分類誤差を検証する。

## ページ再開の改善（追加実装）
- `state["sweep_pending"]` にタグごとの対象時間区間・次のページトークン・取得ページ数を保存する。API枠が足りなくなっても、次回の実行で続きのページから再開する。
- YouTubeの検索結果上限（1区間最大500件）に到達したときは、区間をさらに細分化して再試行する。上限に達したトークンは引き継がない。
- 最小区間でも500件の制約に達した場合は `state["sweep_blocked"]` に失敗区間を記録する。過去の検索カーソルは勝手に進めないため、データの欠落を「完了」と誤表示しない。
